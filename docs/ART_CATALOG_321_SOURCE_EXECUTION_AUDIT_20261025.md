## 3. Confirmed implementation differences and risks (source level)

| ID | Severity / confidence | Actual difference | Repro/test requirement |
| --- | --- | --- | --- |
| GFX-01 | **High, confirmed call-path omission** | Canvas full entity drawing invokes `groundMarker()` and `entityShadow()` for in-world actors and structures; Pixi candidates/actor scene and Canvas combat overlay do not invoke an equivalent general pass. Baked individual procedural art is not a substitute for the separate dynamic shadow and marker layer. | Same hero, NPC, boss, structure and prop at fixed position, with ground/contact shadow, selection ring and moving actor at 150% |
| GFX-02 | **High, confirmed call-path omission** | Canvas invokes `entityAura()` and `drawAbyssFlightCues()` per entity; Pixi actor sync plus overlay omit that outer pass. The separate `drawTrueAura` handles owner-approved TRUE boss radiance/crown. Some inner body art may still contain regalia; do not conflate inner art with the live shared aura or crown. | TRUE boss normal/TRUE, ringleader/frenzy actor and Abyss flying boss; compare whole frame and time sequence |
| GFX-03 | **High, directly acknowledged by code** | `PrototypeSprites.draw()` draws `overlay()` after its image. The Pixi native-sprite adapter explicitly returns `additionalArt.proceduralOverlaysNotYetPorted: true` for its GPU texture command. Such differences can affect ranged aim, TRUE treatment and raster variants even when the correct base image loads. | Eligible active raster Ranger/Archer/Goblin cases with aim/TRUE/overlays, at matching event times. Don't claim successful Pixi parity solely because `loadedTextures > 0`. |
| GFX-04 | **High, confirmed call-path omission** | Canvas full renderer iterates current `game.s.loot` and calls `drawCrownLoot()`; Pixi visible candidates do not include loot and the Canvas overlay draws no Crown loot. A user may therefore lose important pickup visibility while the GPU world is active. | Spawn real Crown loot, establish active WebGL2 backend, capture both modes and verify pickup readability without gameplay changes |
| GFX-05 | **Medium–High, confirmed call-path omission** | Several entity-local visible states in the full Canvas entity loop are not invoked in the Pixi actor or overlay path: Ridge `ledgerOpen`, ledger-mark floor circle, special Keeper cage frame, enemy `pursuitBurst`, and some bundle/recruitment details. Some generic combat cues remain in Canvas overlay and must be separated from these specific missing layers. | Focused screenshots/time sequences for each mechanic and exact scene state; distinguish missing cue from a differently drawn equivalent |
| GFX-06 | **Medium–High, documented source-route discrepancy** | Canvas atmosphere collects carried Wraith lanterns separately and can draw up to eight; Pixi `syncAtmosphere()` collects props/buildings/service NPC lights but not those carried Wraith sources. Both have day/night lighting, but they are not equivalent source sets. | Same Wraith night scene, same camera/time; verify carrier light positions, dark ambient legibility and GPU lamps |
| GFX-07 | **Medium, source test gap** | Existing `tests/pixi-fidelity.test.cjs` has substantial mocked renderer safety checks. The browser test validates real Pixi startup, actor count, texture sources, camera, lighting transitions, Keep/Revert, and specific Mage beam Canvas overlay behavior; neither defines per-ID actual screenshot parity across all 513 historical entries or the ten newly observed cases. | Build a dedicated paired-capture artifact and per-ID review ledger; do not relabel existing browser smoke as exhaustive art certification |
| GFX-08 | **Medium, verify under device conditions** | Pixi body `bake()` uses a Canvas draw of `PrototypeVisuals.draw()` and caches a resulting texture by revision. The cache revision includes zoom, density, zone, identity, rescued/form/presentation/crowned, but not every time-dependent source art input. Background is independently offscreen Canvas-based; difference in animation/facing, contextual art and transitions is plausible. | Live sequences for moving environmental props, actor changed states, day/night and first/revisit textures; measure live framebuffer, not only source intention |
| GFX-09 | **Medium, deferred branch dependency** | The Ranger/Paladin/Archer arrow/impact work in #464 and the dormant critical indicator effort in #440 remain draft/unmerged at this main snapshot. Their final runtime presentation can change the true asset/effects universe; do not preapprove against outdated flight/cue behavior or silently include unmerged behavior. | Re-pin source after merges and add affected projectile/critical event cases separately. Keep current render behavior as the present baseline |

## 4. Audit completion and promotion gates

**Completed now:** independent original-data integrity check, manifest membership delta, current scope-case crosswalk including all 513 historical IDs and 10 new cases, actual renderer call-path comparison, explicit source-level gap register, pinned source/version, outstanding evidence limits.

**Not completed and not claimed:** real paired Canvas/Pixi screenshots; real iPhone/Chromebook/WebGL devices; comparison across day/night, movement/crowds and all skills; 513 individual actual live visual pass/fail decisions; performance gain measurement; corrected game code; native or full-browser regression execution.

A safe next audit batch should first establish that Pixi is *actually active* (not silently on fallback), then capture **one genuine target for each GFX-01 through GFX-06** while preserving exact simulation state and checking both renderers. An exhaustive per-asset visual pass should start only after the capture method is verified and its evidence proves a real screenshot rather than a mock. Maintain owner-approved Canvas artwork as canon; do not modify art or simulation merely to make a screenshot test pass. In any implementation follow-up, separate minimal fidelity fixes from broad renderer or performance redesign, keep the project multi-file, and leave Canvas the safe default until the owner authorizes promotion.

**No merge, live deployment, game code, art, save, workflow or full-suite execution was made by this audit.**
