## Why a blanket rollback is unsafe

A whole `git revert -m 1 323bb2a7` would remove the **entire** Greenwood release as well as these cross-region repairs, affect build/asset/version/documentation changes and conflict with later `main` work. Resetting `main` to the old SHA would also discard unrelated releases, including dev.234 companion improvements. Neither is an appropriate non-Greenwood-only remedy.

Even a precise code revert can leave **already-migrated v4 saves** with moved road vertices, props, service positions and receipt fields. Existing code **cannot be assumed to run those migrations backwards**. Removing a version flag is not a reverse migrator and might run an old mutation twice. Preserve pre-upgrade exports; never overwrite a newer player save just to reproduce historical visuals.

## Selective rollback design — draft review gate

**Default: preserve all non-Greenwood source until each regional before/after image, route and save delta is measured and reviewed.** A successful automated road audit is evidence of road assertions, not an owner request to redesign another province.

1. **Freeze baselines and classify.** On an isolated read-only checkout, materialize fresh seeded games and at least one genuine protected v4 backup for each other region (when available) at `87792f64` and `323bb2a7`. The 29 October historical branch `recovery/greenwood-pre-flagship-20261029` is *earlier* than immediate pre-merge and must not silently substitute for `87792f64`. Keep copies isolated to prevent automatic migrations from mutating the original backups.
2. **Compare same scene/seed/zoom.** Capture town/refuge/hamlet, major transport and bridge, Treasury, representative creature habitation, road joins and wilderness. Produce a before/after position census by stable prop/NPC/road ID (including counts added, moved, removed), collision/clearance and native route results. For Frontier/Crown specifically, record all objects changed by the shared finalizer, not just the anchor services.
3. **Make region-by-region dispositions.** Mark each difference **retain**, **rollback**, or **redesign separately** using evidence and the existing approved regional visual contracts. Preserve already-acceptable parts; do not substitute automatic road expansion for human review. Avoid rolling back fixes that prevent trapped players without first providing an alternative safe approach.
4. **Prepare the actual rollback implementation in this separate draft PR only after determining the exact wanted deltas.** Isolate removals/replacements by region; avoid a whole-merge revert. For new games, restore the original authored result only for selected regions. For migrated saves, choose between explicitly tested reverse positioning of existing stable IDs/roads and preserving the upgraded geography with accurate disclosure. Never delete player Barracks, quest progress, saved actors, crowns or discoveries.
5. **Validate focused and source-first.** Original `town-street-audit`, `local-sites`, `ironroot-highlands`, geographic route/entrance checks and **pre/post repeat-restore v4 tests**, plus exact same-camera screenshots and offline build, must be reviewed on the rollback head. If a previously green strict road assertion becomes red, do not weaken it; explicitly demonstrate the pre-change routing was acceptable or design a narrow alternative.
6. **Publish only with owner authorization.** After final branch and test receipts, the owner decides if the before/after is actually preferable. No merge, automatic Pages deployment or device verification is implied by this draft.
