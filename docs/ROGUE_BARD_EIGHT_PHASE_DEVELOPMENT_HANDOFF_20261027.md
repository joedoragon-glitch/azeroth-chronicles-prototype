Separate **normal/tap** and **charged** Skill 1 have capped enemy AoE and the mirrored short **Sharp Refrain** buff to in-area **living active companions' ordinary basic damage only** (+5% for 4s / +7% for 5s, first-pass figures). No manual Skill 1 Charm rolls; future Charm **may trigger only from surviving lawful auto-basic primary damage**, never splash or manual performances. - `src/prototype/combat.js`, `src/prototype/save.js` and companion methods: **Endure** leaves Rogue at 1 HP on the first lethal hit in a life, protects against further HP hits for 2 simulated seconds; its used flag persists per life but the live invulnerability clock and companion song buffs do **not** persist across save. No approved 90s retrigger policy is asserted. Existing original-class combat paths are intentionally unchanged.
- `src/prototype/skill-reference.js` exposes Skill 1's three forms for staged Rogue testing. **Skills 2–8 are not live; Charm, separate critical control, sprites, recorded sounds and in-game class selection are not shipped.**

## Binding character and game design, in priority order

1. **Original owner direction** in [discussion record](ROGUE_BARD_DISCUSSION_RECORD_20261026.md) is **the first-play canonical baseline until the owner can playtest**. The linked [static visual specification](ROGUE_BARD_STATIC_VISUAL_DESIGN_20261026.md) supplies a usable first-pass normal/crowned outfit: female, darker warm-brown complexion, long uncovered black hair, expressive/glamorous/sassy face and South Asian/Middle Eastern/Persian-influenced sari-like violet/plum/copper traveling drapery, practical skirt/trousers, jewelry. Reference images **only** establish the new weapon, not clothing.
2. **Later explicit owner corrections trump older documents**. The **guitar is retired**. Weapon: **staff with one oversized spherical jingle bell suspended from it**; basic sounds are **short bell jingles**. No animated character rig requirement. Original manual repertoire titles and auto names are **historical prototype names**: owner has reopened them because she wants grounded, readable names expressing this character's lore and each hostile/friendly action, **not generic ballet/concert titles**. Do not silently invent a final naming canon.
3. **Fresh Rogue starts alone** (no Soldier/Archer); never recruits *new* conventional Soldiers/Archers. **Succession Rogue inherits the company** including ordinary Soldiers/Archers, pets and all previously Charmed monsters, retaining IDs/ownership/reserve/fallen; a non-Rogue successor keeps owned captures but cannot Charm more.
4. **All authentically Charmed ordinary monster subtypes can perform existing labor** (Barracks construction/resume/upgrade and gathering when progression permits) while retaining exact monster combat identity. Rogue **delegates**, never bypasses native construction to build personally. Fresh tutorial is **Charm successfully first → then Build Barracks → gathering after Expedition Rank 2**. Succession must not force a fresh-game Charm tutorial.
5. **Roster quotas:** effective Rogue active caps per Expedition Rank 1–6 = **3/4/4/5/6/7**; cap **owned monsters per *exact subtype*** (active/reserve/fallen/away), not arbitrary total 12. Basic Barracks local Add cap **3**, Full Barracks local cap **Expedition cap**, roster pagination. Captains/ringleaders/bosses cannot be Charmed. Suggested **12% opening primary-hit Charm frequency is not yet owner-approved**, must pass real first-ally survival/onboarding tests.
6. **Performance rules:** all **eight normal + eight charged** authored manual skills must be actual combat-only dual-sided AoE with a negative enemy outcome and a conceptually inverse positive outcome for eligible nearby companions. Same-family statuses use one bounded strongest nonstacking instance; different families may coexist within tested limits. Rogue does not receive the companion boon under current candidate. No expensive per-frame global scan.
7. **Technical platform:** Azeroth Chronicles is a **multi-file** GitHub Pages/PWA app. Keep native Canvas2D and experimental optional Pixi WebGL paths safe. Do **not** impose obsolete single-HTML portability, introduce unnecessary actor simulations/animated bodies, or change three old playable classes to implement Rogue.

## Phase 3 code checkpoint — 27 October 2026

Authentic Charm is now staged behind the unregistered Rogue gate. Only an actual HP-reducing surviving automatic-basic **primary** damage receipt enters the positive ordinary authored enemy allowlist; guards, captains, ringleaders, bosses, summons, night actors, owners, neutral/returning and reset-protected foes are excluded. Splash and manual Skill 1 never roll. Exact keys derive from authored species plus actual melee/ranged variant, never display text. Quotas equal 3/4/4/5/6/7 by Expedition rank **per subtype**, counting the full active/reserve/fallen/away roster. A full field sends the new ally to reserve without Barracks. The separate saved Charm LCG consumes no draws for ineligible/quota-denied cases; 12% is a provisional playtest rate.

Successful conversion creates one ordinary friendly roster actor with exact source metadata, normalized HP fraction and stable identity; it removes the hostile, clears attack references and bypasses kill/XP/gold/quest/streak receipts. Save v4 checks an exact-source capture ledger, allowlisted subtype, unique hostile source and absence of the original enemy; a forged standalone flag fails. **Client-edited saves cannot be cryptographically authenticated without a server-held key**, so this is structural integrity, not anti-cheat certification. Phase 4 still owns species-specific behavior, recovery and native labor; Phase 7 owns the Charm-before-Barracks tutorial. Rogue remains unselectable and PR #511 remains draft/unmerged/undeployed. Newer mainline title/renderer changes beyond `990fc79d` still need reconciliation. The focused CI result for this code checkpoint must be confirmed separately before declaring Phase 3 verified.

These are Phase 3 identity safety changes; full species-specific recovery balance remains Phase 4.
