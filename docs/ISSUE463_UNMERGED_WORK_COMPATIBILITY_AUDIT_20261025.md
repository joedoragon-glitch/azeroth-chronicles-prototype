## Audited preservation constraints / actual implementation notes

1. **Ranger native arrows:** moving bow positions only at actual release; no fabricated hits/Slows before collider contacts; preserve Paladin's planted double Cross and Mage charged Beam living corridor. Three simulation step sizes were tested, but real-device readability and latency are not measured.
2. **Critical receipt interface:** `petSkillContact(pet,victim,slot,1,criticalReceipt,launchPoint)`. The fifth and sixth fields now carry independent values in #464, but **#440's receipt processors are not integrated**. On later reconciliation, critical is decided once at legal release and held through ranged contact; Archer Piercing Volley critical effect must travel with each real arrow, not be spent in an instant area-damage loop. Ranger Pinning Volley should keep its two existing Slow sources without duplicate enhancements.
3. **Pet/audio ownership:** pet real bolt has stored launchX/launchY, no false full-range impact tether; `physicalProjectile` only suppresses an extra cosmetic line. #472 adds missing impact sound for pet style `pet`. Archer `projectileLaunch` *initial* event remains a legacy planned `count:3` three-arrow cue; subsequent actual individual `projectileLaunch` receipts have `projectileId`, `releasedCount:1`, `presentationHandled:true` and therefore do not schedule *new whole-volley foley*. This preserves the sound owner's established first cue and honest real-contact record.
4. **Effect diagnostics:** #471 stores counts by *event type*, not by departed projectiles. `receipts.projectileLaunch` counts event objects; it is **not a count of individual arrows**. A later integration should explicitly report physical released total by `releasedCount ?? (count - pendingCount) ?? count ?? 1` for relevant positive-shaft events, disambiguating duplicate `heroProjectileFlight` as a second *observation of the same arrow*, never additional projectiles. The 40-effect queue, opt-in developer-only mode and no background work are mandatory.
5. **Rendering composition:** preserve #464's `drawPetSkillGeometry` suppression for actual projectiles, `projectileVolley` 0.16-second cast cue and 0.24-second Soldier melee cue; #471's protected first-paint and 24 enemy-status cap; #469's shared pause layer and Crown loot. These touch different conceptual portions of `renderer.js` yet need joint execution evidence.
6. **Native crowd vs hardware evidence:** one focused fixture created ~29 actual targets and verified delayed physical contacts and <=40 transient queue. It is **not** proof of FPS, draw visibility or accepted gameplay balance on hardware. No real-device/slow-motion or Chromebook benchmarking.
7. **CI:** #464 `cf6074e` [focused check #40228499106](https://github.com/joedoragon-glitch/azeroth-chronicles-prototype/actions/runs/40228499106) passed 31 selected files and reproducible build. This remains *historical* after the audio-event fix in this audit: **check new exact-head CI before marking current draft green**. Other passing PR runs have their own independent source heads; never equate those with a tested combined tree.
