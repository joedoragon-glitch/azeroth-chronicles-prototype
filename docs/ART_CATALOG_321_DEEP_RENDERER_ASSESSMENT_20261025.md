## Executive assessment

**Do not promote experimental PixiJS/WebGL2 to the default renderer on present evidence.** It is an actual usable GPU scene implementation using the same simulation, not a mock; it deliberately retains Canvas for terrain generation, procedural-art creation and combat cues. The risk is **incomplete presentation equivalence**, especially dynamic positioning/facing, temporal procedural art, entity-local ornament/cues, transparent world overlays, and background invalidation. Some failures are source-level confirmed missing calls; others are testable risks awaiting exact real browser image evidence. A successful GPU startup, texture preload or fallback cannot certify any individual asset's visual parity.

**Do not reopen already approved art:** the 513-case original catalog and the later #323 implementation record all 465 refinements/rebuilds, 47 protect recommendations and one effects-context review. The complete original 513-row CSV records completed-design acceptance dated 19 October; that creative acceptance remains. Current game routing and **WebGL presentation parity** are distinct dimensions. The source crosswalk validated all 513 stable IDs, 188/188 historical decoration cases, 15/15 structures, 26/26 landmarks, 33 current raster registrations with changed membership, five current textures and ten post-catalog decoration cases. Ten additions are source cases, **not** ten approved new sprites.

## 1. Actual architecture and call chain

The canonical game remains a multi-file GitHub Pages/PWA and one authoritative Campaign. Canvas 2D is the default. The user-selectable GPU renderer is PixiJS v8/WebGL2 behind an explicit Keep/Revert trial, with recovery to Canvas. Do not claim the migration is complete or independent of Canvas.

| Visual stage | Canvas full mode | Pixi experimental mode | Evidence and boundary |
| --- | --- | --- | --- |
| Static world terrain, roads, floors, bridges | `PrototypeRenderer.render()` paints directly | A separate **Canvas** `PrototypeRenderer` painted as `renderLayer='background'` produces a raster, uploaded into a GPU sprite | [Renderer](../src/prototype/renderer.js) around L2143–2300; [Pixi background](../src/prototype/pixi-experimental.js) L192–315. It is not native GPU terrain |
| Actual actor appearance | Selection via `PrototypeSprites.draw()` or procedural `PrototypeVisuals.draw()`; animated position, facing, shadows and layers | Pixi adapter selects active raster textures, or individually **Canvas-bakes** a procedural body and retains it as texture; actor positions updated on GPU | [Canvas actor](../src/prototype/renderer.js) L493–605, L2435–2680; [GPU actor](../src/prototype/pixi-experimental.js) L317–422 |
| Environmental light/night | `PrototypeVisuals.atmosphere` and additional world effects after entities | `scene.syncLamps`, `setAtmosphere`, `setVignette` on the GPU world | [Canvas environment](../src/prototype/renderer.js) L2690–2805; [Pixi light](../src/prototype/pixi-experimental.js) L424–479 |
| Combat warnings, projectiles, many status cues | Full Canvas render, ordered by original entity/effect phases | **Canvas overlay** above GPU world: `PrototypeCombatVisuals.ground`, `PrototypeEnemyVfxArt.ground/actors`, `drawProjectile`, `drawVisualFx`, hero status/charge/queued and target guidance | [Overlay](../src/prototype/renderer.js) L2143–2180. These are preserved 2D cues and must not be declared absent wholesale |
| Presentation process | One Canvas frame from the shared Campaign | The same Campaign; Pixi world first, Canvas cue overlay second; on failure controller exposes Canvas and disposes GPU resources | [App switch](../src/prototype/app.js) L1795–1910; [Pixi recovery](../src/prototype/pixi-experimental.js) L596–673 |

The conditional rendering path and **which layer owns an image** must be included in every subsequent asset verdict. "Displayed in WebGL mode" is not synonymous with "drawn natively by WebGL." The latter may be GPU-textured Canvas art or a transparent 2D overlay; that is acceptable **when visually and functionally faithful**.

## 2. Findings register — severity is potential impact, not a made-up screenshot result

### Critical candidates / verify first

**DR-01 — Procedural actor left/right facing is not applied in the Pixi painter (source-confirmed divergence).** Canvas uses `paintedFacing(e)`, prioritizing combat target/motion, and mirrors its body about the foot anchor at [renderer L529–596](../src/prototype/renderer.js). Pixi's procedural `bake(painted)` calls `PrototypeVisuals.draw` directly without this mirror; its records set `flipX:false`, and `revisionFor` has no facing. The body can move on the GPU without turning as the original Canvas body would. **Scope candidates:** ordinary enemies, bosses, companions/pets, NPCs, crowned hero procedural bodies. **Test:** side-by-side deterministic west/east motion and targeting while stationary and while strafing, including Orc/Cinder, Wraith, Rider, summoned pet, crowned Ranger/Paladin/Mage. **Do not infer all assets have visibly asymmetric bodies.** Evidence: [Pixi L89–126, 248–255, 317–418](../src/prototype/pixi-experimental.js).

**DR-02 — Raster facing propagation is disconnected (source-confirmed).** The GPU raster adapter's `commandFor` has `facing=1` by default, and [actorFrame](../src/prototype/pixi-experimental.js) calls it without an explicit facing argument. Although the adapter computes a directional `pose.facing` for eligible directional animation clips, it passes the **default scalar facing** to `gpuCore.spriteLayout`, which controls left/right `flipX` ([native-sprite-adapter L30–115](../tools/webgl-pilot/native-sprite-adapter.js), [native-webgl2-core L27–60](../tools/webgl-pilot/native-webgl2-core.js)). This differs from Canvas `paintedFacing`, which also uses attack targeting. Direction-specific authored clips could partially compensate but cannot prove equivalent mirroring. **Test:** Ranger, Goblin Archer and retained Goblin raster in left/right walk, target switch, combat idle and clip frame.

**DR-03 — Baked procedural imagery does not track temporal/mutable body art (source-confirmed limited cache key; visible impact untested).** `revisionFor` uses backing ratio, zoom, actor key, zone, rescued flag, `form`, `presentation`, `crowned` but omits `ambientTime`, attack/aim, animation pose, stage progress, several visual state fields. A body is painted once until this key changes/evicts ([Pixi L248–255, 317–417](../src/prototype/pixi-experimental.js)). The original procedural visual source explicitly animates `ambientAnimalPose(e, ..., e.ambientTime)` ([visuals L10148–10155, L15512–15520](../src/prototype/visuals.js)); `presentEntity` updates ambientTime from the live presentation clock. Thus **ambient animal motion inside composite bodies may freeze** while the GPU moves the outer image. Aim/state decorations baked after first display may also go stale. **Test:** moving livestock/animal pen, Mire nest, aimed ranged enemies, body/state change without zone/zoom transition. This is not a simulation defect.

**DR-04 — Crown loot not part of GPU actor universe or 2D cue overlay (source-confirmed missing visual call).** Full Canvas draws all current-zone loot via `drawCrownLoot(ctx, screen(l))` after actors ([renderer L2674–2690](../src/prototype/renderer.js)); Pixi candidates contain props/NPCs/nodes/buildings/enemies/party/hero but not loot, and overlay has no loot call ([Pixi L45–87](../src/prototype/pixi-experimental.js), [renderer L2143–2178](../src/prototype/renderer.js)). **Impact candidate:** coins/rewards can become invisible while the GPU world remains active. **Test:** real live loot before/after pickup in both modes, assert active backend and untouched pickup mechanics. Historical review owner: `shared:loot`.

**DR-05 — Game-significant entity-local visual layers omitted or differently composited (source-confirmed).** Canvas full entity pass draws `groundMarker`, `entityShadow`, `entityAura`, `drawAbyssFlightCues`, `pursuitBurst`, Ridge `ledgerOpen`, ledger-mark rings, Keeper cage bars, some bundle markers and other actor-local geometry. The GPU actor list and Canvas overlay do not reproduce that full per-entity layer ([renderer L750–837, L2435–2610](../src/prototype/renderer.js), [overlay L2143–2178](../src/prototype/renderer.js)). Some body-internal details and generic combat warnings survive, so do not assume every cue is completely invisible. **Test:** priority named states under exact live conditions; especially selection/contact grounding, Ridge ledger/mark, Abyss flight, Keeper captivity, bundles and retreat/approach cues.

**DR-06 — TRUE boss effect composition is not equivalent (source-confirmed separation; no claim that crown is absent).** The procedural artist already draws the accepted shared spectral/TRUE crown inside the boss body for `form==='true'` ([visuals L17535–17582](../src/prototype/visuals.js)), so **Pixi's procedural bake can contain the crown**. But Canvas additionally calls the live `entityAura/drawTrueAura` effect, and renders a separate TRUE badge/label treatment in the entity loop ([renderer L79–150, L813–845, L2540–2585](../src/prototype/renderer.js)); the Pixi overlay's `drawPixiNameplates` uses a generic boss name format and lacks that same badge. Distinguish **body crown present**, **live aura missing/different**, **nameplate/badge differs** and **possible crop/headroom**. Test all 11 TRUE bosses at night with movement and effects, not a single still.

### High / targeted fidelity and safety

**DR-07 — Raster overlay and Frontier-tree finish not ported (confirmed in the adapter contract).** `PrototypeSprites.draw` paints `overlay(ctx, e, p, entry, scale)` for selected images and the Canvas renderer may add `frontierTreeShoots`. The Pixi adapter explicitly reports `additionalArt.proceduralOverlaysNotYetPorted: true` and a dead-tree-specific shoots flag ([sprites L692–715](../src/prototype/sprites.js), [adapter L115–125](../tools/webgl-pilot/native-sprite-adapter.js)). These flags are NOT, on their own, claims every raster requires every overlay; verify exact eligible states. Test ranged-aim and event overlays plus currently selected Frontier trees.

**DR-08 — Scene occlusion/highlight pass lacks equivalent (source-confirmed absent call; severity depends on context).** Canvas performs `drawOcclusionOutlines(entities)` after environmental grading to keep important actors visible through cover ([renderer L659–748, L2800–2805](../src/prototype/renderer.js)); the GPU actor scene and Canvas overlay do not call this masking/cover pipeline. Compare actual overlap by walls, buildings, tall nature, banners, crowds and boss sprites. Depth order alone does not provide cover-specific highlighting.

**DR-09 — Wraith-carried lights not included in Pixi night source set (source-confirmed).** Canvas generates up to eight position- and facing-aware `carried-lantern` sources for living Wraiths, then passes them alongside environment lamps to atmosphere ([renderer L2736–2792](../src/prototype/renderer.js)). Pixi `syncAtmosphere` gathers fixtures, complete buildings and service NPCs, but not those Wraith sources ([Pixi L424–479](../src/prototype/pixi-experimental.js)). The GPU core *supports* carried-lantern shading; its actual caller omits them ([native-webgl2-core L65–95](../tools/webgl-pilot/native-webgl2-core.js)). Check `enemy:wraith`, crowded nighttime Wraiths, dark scene legibility and lighting positions.

**DR-10 — Certain boss/area ground effects do not reach the Pixi Canvas overlay (source-confirmed).** Canvas full render directly draws Warlord Choking Ash from `ashCloud` after atmosphere ([renderer L2780–2801](../src/prototype/renderer.js)); the overlay renders generic `PrototypeCombatVisuals.ground` and `PrototypeEnemyVfxArt.ground`, but not this explicit renderer-local cloud pass. This is **not** a claim that all combat telegraphs are missing. Test `boss:warlord` with a real active cloud, consistent clock and backend; compare danger-region visibility and actual hit mechanics.

**DR-11 — Combat cues survive, but their compositing order differs (source-confirmed architecture).** Canvas full mode draws some warning/ground passes **before** standing actors and other effects **after** them. In Pixi mode all Canvas overlay passes necessarily sit **above** the separately rendered GPU scene. Thus the same warning pixels can obscure an actor or lack scene occlusion even when emitted correctly ([renderer L2289–2301, L2143–2178, L2801–2809](../src/prototype/renderer.js)). Compare dangerous telegraphs, charge targeting brackets, health plates, projectiles, boss hazards and densely overlapping props as moving frame sequences. **Do not suppress essential warnings merely to match old z-order.**

**DR-12 — Labels and social-state decorations use a separate simplified implementation (source-confirmed).** `drawPixiNameplates()` reserves names with its own priority, abbreviations, formatting and service prompt, unlike full Canvas entity drawing (different TRUE labels, captain treatment, NPC state/status and some interaction indicators). The initial early audit should not treat the presence of any text as exact naming parity. Test `captive:*`, `appointed:*`, `boss:*`, `crown-troop:*`, crowded settlement service actors, screen-edge names and phone UI clipping ([renderer L2063–2141 vs L2380–2680](../src/prototype/renderer.js)).

**DR-13 — Background invalidation is driven by camera/zone/zoom/optimization, not an explicit world-content revision (confirmed mechanism, stale-world symptom unverified).** `syncBackground` invalidates on base game/zone/zoom/optimization, or after a bounded camera displacement; it does not read a revision for roads, bridges, terrain appearance or other map content ([Pixi L275–316](../src/prototype/pixi-experimental.js)). If a stateful background feature changes with no camera movement, old pixels may remain until rebake. Test controlled region/civic-state transitions, completed construction and location/water states that genuinely modify the background, and never invent a dynamic case if it is actually static.

**DR-14 — Native sprite memory and staged art work need actual-device evidence (source-confirmed allocations, throughput unmeasured).** For every not-yet-cached procedural candidate, `bake` allocates a square offscreen Canvas of `round(576 × backingRatio × cameraZoom)` on each side, draws vectors and scans a full RGBA `getImageData` buffer before cropping/uploading. A 150% camera with 2× backing ratio implies a 1728×1728 staging canvas (about 11.9 MB of raw RGBA pixels **per staging surface**, before any additional buffers, texture upload or runtime overhead); higher zoom/quality increases this cost. The procedural texture budget is 256 MiB with LRU trimming, but it is **not a measured total device GPU memory ceiling**. Verify first reveal, zoom/region churn, crowd/frequent new actors, WebGL loss, and device latency without claiming speed improvements. See [Pixi L89–129, L160–190, L235–270, L355–420](../src/prototype/pixi-experimental.js).

**DR-15 — PWA/texture fallback, save and frame timing must remain separate gates.** The controller checks WebGL2, preloads registered image resources and may revert to Canvas on failure; Pixi is optional and its effects retain 2D work ([Pixi L497–671](../src/prototype/pixi-experimental.js), [app L1800–1925](../src/prototype/app.js)). A fallback *passes safety* but *fails that trial's WebGL parity evidence*. The report's synchronous Pixi and overlay timings do not measure GPU-completed display latency; adaptive frame skip/emergency holds must be counted separately. Do not make a default-renderer decision from actor count, texture count, a passed build, or self-reported FPS alone.

## First actual browser observation — Crown loot (Stage 1 proof of visibility gap)

A [real Chromium/SwiftShader pixel probe](evidence/ART_CATALOG_321_CROWN_LOOT_RUNTIME_PROBE_20261025.json) exercised the live game renderer at 1280×800 in the Vale using a temporary `Campaign.s.loot` coin (same object shape as native enemy rewards, not an authored kill). It compared the *same renderer mode before and after injecting the coin*, then removed the fixture.

- **Canvas 2D full mode:** the coin modified **870 of 2,401 sampled pixels** (aggregate channel difference 168,712). This confirms the actual coin draw occurs.
- **Pixi WebGL2 mode:** WebGL was active and confirmed, reporting **95 actors** and **115 texture sources**; the transparent Canvas combat-cue overlay changed **zero of 3,249 sampled pixels** (aggregate difference 0) when the coin was injected.
- **Source triangulation:** the full Canvas path draws `game.s.loot` via `drawCrownLoot`. Pixi actor candidates do not include loot, and the overlay has no equivalent call. These independent checks make `DR-04` a **high-confidence missing-presentation finding**, beyond merely a code-structure hypothesis.

**Honest boundary:** the measurements captured the Canvas surface for each backend, *not* a GPU framebuffer comparison or owner-reviewed composed PNG pair. The pre-existing browser journey changed zoom between modes; its samples are therefore **within-mode before/after** and should not be treated as matching-zoom screenshot parity. The original job [#40221978087](https://github.com/joedoragon-glitch/azeroth-chronicles-prototype/actions/runs/40221978087) logged both successful samples but later failed an existing context-loss diagnostic; a second attempt [#40222201465](https://github.com/joedoragon-glitch/azeroth-chronicles-prototype/actions/runs/40222201465) encountered an optimization/background refresh timeout **before** its isolated art probe. Neither run should be presented as a wholly passing browser suite.

To avoid contaminating existing renderer-recovery tests, the expanded browser smoke was restored exactly. A separate [opt-in real-browser image collector](../tools/visual-review/art321-crown-loot-browser.cjs) now captures two composed PNGs, source commit, scene/backend metrics and `evidence.json` when run in an environment with the repo's installed Playwright/Chromium. That collector is **not claimed to have run or produced PNGs in this audit**. It does not need to be merged or deployed. The source-only 513 entry ledger stays visually unaccepted; this runtime defect evidence belongs to the separate evidentiary layer for `shared:loot`.

## 4. Decision-ready implementation dependency order (future work only)

**Gate A — Evidence harness:** Build a true matched-camera/world-state capture that can prove the backend used, distinguish GPU actor texture from Canvas overlay, pin SHA/build and case identity, and capture before/after sequences. Require at least one real WebGL2 scene and forbid a silent Canvas fallback from becoming a "pass". Have a separate source-only **unrendered/unreachable** disposition instead of fabricating images.
