# Specialist Nightmare coverage after dev.145

This completes the first bounded follow-up from [the historical test-drift review](TEST_DRIFT_HISTORY_DEV145.md), resumed at Joel's request after the sound investigation. Six original specialist suites now distinguish Normal daylight, fresh Nightmare sunset, actual post-sunset Nightmare and restored pre-intro Nightmare saves. Two additional stale fixture assumptions are corrected. These checks have not established a new gameplay defect. Runtime remains dev.145; this change updates tests and documentation only.

## What was missing

Since dev.121, a new Nightmare campaign has 30 seconds of sunset. Calling only `updateEnemies` or individual attack owners does not advance that global timer. All six reviewed matrices constructed fresh Nightmare campaigns without explicitly ending sunset, so their difficulty labels did not establish permanent-night coverage. They exercised real attacks and cleanup, but at grace-period scaling/tempo.

[The shared fixture](../tests/helpers/specialist-night-context.cjs) now asserts the starting phase, HP/damage multipliers and tempo for every matrix context. Post-sunset cases call the actual `advanceDaylight` owner. Legacy cases restore a real snapshot with the pre-intro fields absent, then assert permanent night. Neither case replaces `night()`, enemy movement, terrain or damage owners. Fresh grace remains covered rather than being silently converted to full night.

## Limits and next review

The earliest confirmed historical drift remains dev.96; this package closes the specialist phase gap introduced by dev.121 and another actor-identity assumption affected by dev.131. It does not imply every implementation since dev.96 was defective. Existing forced mechanical cases are still distinct from the explicitly listed natural selector pilots; fatal Dreadmaw coverage was not expanded to every phase in this package.

The next proposed package remains native enemy reach, cover and fort interactions: `enemy-reach-regroup`, `fortifications`, `monster-forts` and `treasury-fortifications`, using actual authored actor flags. Wider Treasury/camp pending-effect/reward checks and targeted damage-layer checks remain subsequent candidates. No new defect from this first package requires a gameplay repair before Joel can continue playing. No broad CI, device matrix, version bump or deployment is needed for test/documentation maintenance.
