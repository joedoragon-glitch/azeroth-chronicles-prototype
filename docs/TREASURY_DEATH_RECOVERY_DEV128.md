# Regional Treasury death-loss recovery — dev.128

Owner approved the recovery loop: actual crowns removed by death penalties accumulate in the death region's Treasury. Defeat its captain to unlock collection. A separate marked seized-crowns cache pays the whole balance once and resets it only when collected. Later deaths build a new balance, and captains return for later recovery attempts. The captain-defeat announcement reports the exact recoverable amount.

Frontier has no Treasury interior. The owner selected the existing **Cinder Warlord** as its regional recovery captain, then clarified that this roaming captain must drop the marked cache at his actual kill location; no trip back to a fixed post and no new dungeon. The saved optional `cachePoint` preserves the drop through reload/reentry, and later defeats reposition that single regional cache rather than duplicate it. Vale, Marches, Highlands and Crown use their existing Treasury captains and interiors.

## Rules and ownership

- Existing death-penalty percentages, Basic/Full Barracks reductions and Succession exemption are retained. Fractional last crowns are bounded by the actual wallet debit, so recovery never creates an extra rounded crown.
- Each region has an independent v4 `treasuryRecovery` account: `crowns`, `unlocked`, `respawnAt`, plus optional Frontier `cachePoint`. Interior deaths credit their parent region before refuge/Barracks travel. New runs start empty; older saves default to empty accounts. Earlier death events lack regional attribution, so old losses cannot be backfilled reliably and are not guessed.
- Defeating the designated native captain announces `NAME defeated · N crowns recoverable`, preserves the balance and unlocks the cache. Collection requires that captain defeated (or actual peace), the correct regional site, and ordinary interaction range. Other living guards can still fight; this does not require clearing the original supply quest or all defenders. A full payout hides the cache immediately. Repeated/stale interaction and reload cannot pay it twice.
- Original quest caches, collection flags, supplies/quests, victory/rescue progression and existing reward amounts are independent. A refund changes carried crowns without creating XP or counting the same money again as newly earned crowns.
- The captain and defeated native Treasury guards can return 120 simulation seconds after the captain's defeat, once the hero is at least 700 units away from the captain's home and no living enemy in that zone is engaged. Respawn placement checks actual actor radii and separation from heroes, companions, living enemies and other returning defenders. Return is deferred if a complete placement cannot be made. No garrison appears on top of a nearby player. Frontier returns its designated captain only.
- Returning defenders retain stable IDs, authored roles, profiles, base stats and applicable migration versions; combat phases and temporary states start clean. Reinforcements/summons do not multiply into native posts. Returning defenders carry zero new crowns/XP, so repetition is a recovery loop rather than a reward faucet. Peace preserves access to stored crowns and creates no hostile returns.
- New persistent state has strict object/region/number/boolean validation; absent data in older v4 saves defaults safely. No schema/key change or reset of an existing playthrough is required.

`treasury.js` owns the account/site/collection/return lifecycle. `economy.js` owns actual wallet debit/refund; `engine.js` calls the module at death, captain defeat, entry and the enemy update boundary. `save.js` validates/restores accounts. A bounded 0.25-second reconciliation cache prevents repeated full garrison scans. Existing bundle art, labels and subtle cache marker are reused; no generated art or additional rendering surfaces are introduced. The new owner is registered in the campaign inventory/template and the independent audio audition graph; that graph's already-missing fortifications dependency is also restored.

## Arena audit steering retained

The owner clarified that arena work must support prepared defenders using their intended skills, summons and defensive positions; it is not a plan to make clearing dungeons easier. Corner entrances provide separation before confrontation. Initial companion stacking is acceptable; spacing is optional where actual combat movement/performance supports it. **Crypt, Archive and Mine fort bonuses are undecided and not authorized.** Their absence in the audit is not a defect to fix automatically. Death-loss recovery is the current priority. Crag/arena/entrance changes and sunrise/sunset flashes are not part of this release.
