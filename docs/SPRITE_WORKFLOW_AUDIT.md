## Recovery and evidence

Run `npm run sprite:recover` or `npm run material:recover` after an interrupted registration. Validation and further publication reject a pending journal. Recovery refuses a live publisher or registry bytes unrelated to the recorded transaction. Do not delete the journal to bypass that protection. A hard-kill test exercises the interval after the first metadata rename; this establishes process-interruption recovery, not hardware/power-loss durability or cross-machine locking. Retained immutable binaries may remain unused after recovery and are deliberately preserved.

Tests use isolated synthetic resources and do not grant production creative approval. Transaction tests cover stale snapshots, simultaneous publishers, ordinary validation failure, hard-kill recovery, unrelated-edit refusal and binary integrity. Density tests cover the request checkpoint, legacy preparation/rollback, source/translation guards, unchanged runtime geometry, bounded dense atlases, native scene capture and corrupted rollback metadata. Existing material and loader suites cover their normal integration paths. Release browser/device results belong to the exact tested PR head and deployment run; do not carry results forward from an earlier head.

`SPRITE_RESOLUTION_READINESS.json` inventories 33 active sprite keys and 44 retained candidate records. Active retained sources have enough pixels for the target; that does not prove readable artistic detail. Historical batches, prompts, approvals, originals, active image bytes and registry entries are preserved. The new request builder is a planning wrapper: reconcile the actual accepted per-design handoff before generation, and attach the retained accepted source for edits. Catalog wording alone does not establish design acceptance.

Inspect full-size scene PNGs and animation in desktop/phone, day/night and combat context. 4. Record real review/authorized implementation evidence, replace with the exact current lease, run release checks, publish the tested build and verify offline resources. Retain the prior revision for rollback.

Physical-phone performance measurements and artistic judgment remain production checks; synthetic pixel availability and CI emulation do not replace them.
