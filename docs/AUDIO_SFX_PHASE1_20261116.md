Source at `main@66cbf47d251ba3213a61f21e5a3eb1abf57f26df` was inspected; current published-game source is not automatically equivalent to the release candidate.
- **Replace the actual 30 physical WAV bytes** and adjust their SHA-256/duration/credits/authoring recipe; keep 30 IDs, 95 event keys and all binding choices/stage contracts intact. Do not introduce new recorded events or expand skills in this phase. Recorded source is explicitly allowed in `docs/DECISIONS.md`; procedural fallback, cold decode/no-ghost-impact and danger warning priority remain active.
- **Synthesis constraints:** original project-owned sounds, authored material-specific transient/resonator treatments, no external samples or licensing ambiguity; short mono 48k PCM one-shots; unambiguous physical impact only when contact actually happens, dry release separate from impact; avoid a generic cinematic blast, overlong musical tail, or warning-masking low end. Current-level measurements are per-original RMS references, not a universal loudness increase.\n\n## Professional quality gate and evidence limits

The game's `docs/AUDIO_SOUND_PASS.md` and `docs/AUDIO_AUTHORING.md` require intentional distinct creative identity, critical rather than self-affirming checks, sane source provenance, no identical “one template for everything,” short readable attacks, and explicit separation of technical/sound-as-heard acceptance. The first ten-preview study was **revised after finding an overly low-frequency arrow hit and excess bell ringing**, and that initial study is preserved separately (tracked by issue #877). The first 10 are **not** automatically canonical replacements of the 30.

Acceptance criteria:
1. **Source/creative scrutiny:** materially distinct material/stage profiles, known actual event use, protected warnings and special voices; no blind pitch shift of every original or mass-cloned one-shot template.
2. **Real encoded/master verification:** physical 30 WAVs have unique original sha, valid 48-kHz 16-bit mono PCM, bounded duration/headroom/edge envelope and no accidental source aliasing; original 30 hashes remain intact in the frozen archive; catalog has exactly 30 current effects and 84/34 non-effect assets.
3. **Engine/build:** unchanged event bindings and no runtime changes to enemy VFX timing, hero/companion mechanics, mix profile, saves, warnings, PWA fallback or UI; source, browser/playback/cold-cache, build/check and manifest/PWA coverage suites run against the exact candidate. Mark each test PASSED/FAILED/NOT RUN by actual evidence.
4. **Hearing:** owner's **advance** audition is not required; by-ear artistic assessment and real-device combat acceptance remain **unverified**, not falsely asserted PASSED. Owner may report issues in the game after publication; partial/full rollback is always possible.
5. **Delivery:** one review-ready PR based on verified current main and a new **dev.289 candidate** versioned PWA package; **no merge to main, GitHub Pages publication or PWA push without a new applicable owner authorization**.

## Separate Phase 2: recorded coverage expansion, not part of this PR

The current game has 95 authored event-guide identities, only eight keys with recording bindings, and many legitimate procedural hero/companion/enemy actions. Phase 2 should classify **player-perceived gameplay receipts** by class normal/charged/auto Skill 1–8, specials, criticals, enemy factions/boss signatures, allies, rewards, interfaces, movement and environments. Add only sounds with specific meaningful function and stage, preserve original dynamic identity, and avoid overlapping voices/unsustainable assets. In particular, study the Rogue's one spherical staff bell and the four hero classes' actual newly implemented abilities rather than assuming every empty event guide must map to a static WAV. **No Phase 2 production in this Phase 1 PR**.

## Candidate change and rollback policy

The staged PR may be **marked ready for review** when required technical tests pass; owner will not be asked to download pilots or fill out per-cue approvals. **Readiness is not authorization to merge or deploy.** Player-facing source, cache and service-worker versions must update together when permission is explicitly given. If a defect is found later, restore one or all old masters from the frozen archive, verify hashes and build, and prepare an owner-authorized correction without losing v4 game saves.
