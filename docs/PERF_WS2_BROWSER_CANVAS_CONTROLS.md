# WebKit occlusion comparison fixture controls

The original one-frame differential fixture failed on WebKit 26.5 with six changed channels (maximum channel delta 29) in Vale, desktop 1280x800, zoom 1. Full game state remained unchanged. Production sources were not edited during this investigation. The existing frozen 16000ms presentation clock was effective; a missing clock freeze was not the cause.

An independently created baseline painter/canvas using the unchanged occlusion implementation exposed the same failure: the cold baseline/candidate comparison changed 11 channels, baseline/baseline control changed the same 11 channels, and candidate/control changed zero channels. Sprite status showed two queued and two loading resources, although nine images had loaded.

Four uniform draw/readback warm rounds drained those sprite requests (13 loaded, zero queued/loading). Each warm round compared exactly. Nevertheless, performing another batch of three painter draws before any readback changed eight baseline/candidate channels, 14 baseline/control channels and six candidate/control channels. Thus pending sprites alone do not explain the failed comparison. Both failed baseline controls and exact pixel coordinates are retained in `perf-ws2-browser-canvas-controls.json`.

The corrected fixture completes each canvas draw with its own immediate full readback before another painter draws, matching the sampling order of the successful full-painter harness. It retains four uniform warm rounds with bounded sprite-queue draining and freezes all presentation clocks. An initial focused scene passes exact three-way pixels. The precise browser/backend reason for the batched-read discrepancy remains unresolved; the controls establish that this discrepancy also occurs with unchanged baseline code.

Each of all 54 scene/viewport/zoom combinations requires two measured snapshots, exact baseline/candidate/control pixels with zero tolerance, unchanged full game state after every capture, and zero queued/loading sprite resources. Renderer and sprite implementations, asset content, VFX timing, animation, occlusion and simulation are unchanged. The fixture saves reports and failing PNGs before pixel assertions so a failed CI control remains inspectable.

Local WebKit validation passes all 54 combinations (108 exact three-way measured checkpoints), followed by a separate bounded repeat of all six Vale desktop/phone/zoom combinations (12 further exact checkpoints). Every measured capture preserves full game state and has zero queued/loading sprite resources. Raw channel counts, pixel/state hashes, readiness counters and every loaded-module source hash are committed in the control evidence. These local results use WS2's baseline `visuals.js`; the integration owner repeats the fixture with WS1's combined visual source and runs full exact-head CI. This scope difference is explicit in the source hashes. No performance claim follows from the fixture correction.
