## 2. Current rendering architecture — essential for interpreting parity

The canonical game is a **multi-file GitHub Pages/PWA**. Canvas 2D remains the default, safe renderer. [PR #407](https://github.com/joedoragon-glitch/azeroth-chronicles-prototype/pull/407) introduced optional PixiJS WebGL2 world rendering; later fixes through [PR #419](https://github.com/joedoragon-glitch/azeroth-chronicles-prototype/pull/419) stabilized parts of this integration. Both use **one authoritative Campaign**, identical world/simulation/save logic, and a reversible renderer preference. PixiJS is experimental and a **candidate for eventually replacing the Canvas world renderer**, not a certified all-GPU replacement today. The in-game switch provides a 15-second Keep/Revert safety gate and Canvas fallback.

Actual implementation in `src/prototype/pixi-experimental.js`:
- The world **background** is painted by the original `PrototypeRenderer` into an offscreen Canvas then used as a Pixi texture, with bounded refresh/repositioning. It is **not** independently rendered from native GPU terrain primitives.
- The visible actor list is drawn from zone props, buildings, enemies, NPCs, nodes, party and hero, with special handling for some structures/landmarks. Each visible actor goes through the existing `AzerothGpuSpriteAdapter`. Eligible registered raster art is displayed as a Pixi texture; otherwise eligible procedural art is **drawn into an offscreen Canvas and baked into a GPU texture**. These are technically distinct from full Canvas draw calls, but not independently reauthored WebGL artwork.
- GPU textures are preloaded from the sprite manifest; procedural texture cache/eviction and source/zoom/state revision rules exist. New/unavailable art, WebGL context loss, preparation or rendering faults may force Canvas fallback. A fallback is safe behavior but **not evidence of successful Pixi rendering** for the missing case.
- Canvas still draws a **live transparent combat-cue overlay** above the GPU world. Essential warnings/projectiles/health and other cues must be checked separately; the fact that the game appears playable does not prove parity in outlines, translucency, labels, effects, shadows, occlusion, animated visuals or day/night atmosphere.
- The primary Canvas renderer (`src/prototype/renderer.js`) remains the visual/gameplay reference, selecting from `src/prototype/sprites.js` and `src/prototype/visuals.js`; manifest registration alone does **not** imply the raster is selected in either mode.

This design is intentional and appropriate for an experiment; the goal of the future audit is to identify what Pixi faithfully preserves, what it rasterizes or approximates, what it omits, and what would have to change before replacement can be considered.

## 6. Acceptance rules for Pixi as a replacement candidate

- **Parity gate:** no missing gameplay-critical cues or invisible/incorrect actors; every 513 historical review ID classified against the current source with later additions tracked; reproducible matching scene evidence for each *runtime-relevant* appearance/state. Explicitly exclude unused aliases/retired historical assets from fake live-coverage denominators while still documenting their disposition.
- **Safety gate:** reliable Canvas boot and fallback, valid Keep/Revert, resize/context loss/offline recovery, no campaign/save mutations or input/audio divergence, and stable memory under repeated zones and crowds.
- **Quality gate:** native-scale readability, identity, anchor, occlusion, day/night, sprites, materials, animation/event timing and effects are acceptable on actual target devices. Differences judged intentional must be documented and approved rather than silently counted as parity.
- **Performance gate:** compare instrumented matched scenes at known rendering settings, include CPU stage timing and GPU/memory/device behavior. Report FPS/callback/skipped-draw interpretation accurately: source-side Pixi timing is **not** GPU completion time, and adaptive skips/emergency holds can distort raw frame-rate comparisons.
- **Decision gate:** Pixi remains **experimental** until the owner explicitly approves a promotion on evidence. No audit document, catalog count, automated pass or draft PR changes the default Canvas renderer on its own.
