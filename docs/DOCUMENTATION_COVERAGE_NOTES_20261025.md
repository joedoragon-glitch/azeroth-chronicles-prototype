## Conservative registry semantics

`censusSource=oct19_frozen` means *present in the old recorded inventory*, not that its October disposition is current. `censusSource=post_oct19` means *absent from that specific table*, not that the document was created on a verified exact date. `role=dated_record` is a **routing label only**; dated source can still include valid design canon or numeric contracts. `reviewDepth=header_screened` means a bounded first-lines inspection, not full recertification. `reviewDepth=path_only` means the path/Git blob was inventoried but its body has **not** been validated by this pass. `authority=current_entrypoint` is reserved for maintained operational entrypoints and does not override the owner's task-specific approval.

The register deliberately leaves source authority at `verify_with_current_source` for historical and not-yet-reviewed material. **No approval, merge status, numerical truth, or supersession is inferred solely from filenames or the presence of a link.**

## Phase 4 read-only validation baseline (no CI changes in this candidate)

On the checked PR source, [`.github/scripts/focused-ci.cjs`](../.github/scripts/focused-ci.cjs) explicitly limits changed-file test selection to eligible runtime/code/asset inputs: ordinary `.md` files are **not eligible**, and `docs/` is outside its relevant changed-path roots. [`tests/ci-focus-policy.test.cjs`](../tests/ci-focus-policy.test.cjs) deliberately asserts that a changed `README.md` or arbitrary `docs/*.md` selects **zero native suites**. However the existing [focused workflow](../.github/workflows/focused-deploy.yml) still runs the reproducible build check on draft PRs. Therefore a green doc-only PR is evidence of the **build**, not an automatic check of classification, Markdown link paths, selected anchors, or the registry's completeness.

For this candidate the independent post-commit review checks: (1) every Markdown path and its Git blob against the exact Git tree, (2) unique paths and recorded review depth, (3) the frozen 19 October table byte-for-byte, (4) conventional local Markdown file links in changed documents, (5) H1-first and trailing whitespace, (6) the existing focused workflow's actual result. External destinations, nontrivial anchors, full-body factual claims and device acceptance remain outside that check. A tiny docs-specific automated checker could reuse these bounded assertions **only after a separately scoped approval** for selector/tests/workflows; no new test framework or broad browser matrix is justified by this review.
