## Confirmed Priority 4 defects and surgical corrections

1. **Real Skill journal crash:** `menus.js::skillBook` dereferenced `card.name` for every learned slot. `skill-reference.js` had no Strategist card, so Developer Strategist's three learned skills produced null references. Added source-true English/Spanish cards and read-only metrics for Water, Mineral and Fire starter Normal/Charged forms using the existing original Campaign rules; slots 4–8 remain absent. The existing classes and their reference logic were preserved. Developer-only help now explains separate Reversal, real material source prerequisites, Acid usage, and unfinished slots.
2. **Reversal visibility on desktop after companion losses:** Desktop CSS hides `#quick-items` without `.has-rangers`. The Ogre begins with an Archer, but when that companion falls the old visibility computation hid the Ogre's **independent** Reversal action. The HUD now retains the dock specifically for an active Developer Strategist even with no living Archer or healer; ordinary classes use their existing rule. Existing unbound `KeyT` fallback and explicit touch button share the guarded native command. Player-rebound `T` is not stolen.
3. **Unrepresented physical Mineral collider:** `combat.js` correctly owns a single unsaved stationary two-sided one-interception stone face, including an honest charged central opening and collision with friendly physical arrows; however it had no persistent battlefield representation. Added a **read-only** accessor to the very same WeakMap collider and a short stone-lip rendering pass shared by the Canvas world and Pixi overlay. Both painted lips use the actual collider's coordinates and tangential span, with the actual charged notch left blank. No new projectile scan, collision owner, fantasy ward, magic block, persistent state or cache change was introduced.
4. **Incorrect Ogre hints and class identity:** Generic hotbar copy advertised Paladin-style 100→110→120 damage and a 55% frontal combo splash for the Ogre, which the native dagger engine does not have. It now describes three *landed* same-target basics and the finite third-hit Acid behavior (40% area power, bounded to three enemies). Generic charged targeting advice no longer claims the Mineral face locks a target. The Character and status menus now identify the Developer Ogre correctly in English/Spanish rather than showing an undefined class.
5. **Silent refusal:** Failed starter skill release now reports missing genuinely visible Water/Mineral/Fire, or the specific absence of an affected Slow, enemy target or legal facet placement. Material lookup runs **only after a refused Developer skill cast**, not every frame. No extra source eligibility or shortcut was introduced.
