# GTA Cuba Edition

> **Experimental feedback-driven variant, not the standard public game.** Created to accommodate an individual player's preferred controls without changing the owner's general game design. It is not a default mode, not a separate official design direction, and not a validated independent playtest. The standard game on `main` remains authoritative. This document is a developer handoff; the player-facing game retains the usual title.

Development record for the closed, unmerged [PR #872](https://github.com/joedoragon-glitch/azeroth-chronicles-prototype/pull/872). The edition is isolated in `mod/gta-cuba-edition`. Player-facing pages use the standard game title.

## Controls and combat

- Desktop movement and menu navigation use WASD. F or Enter confirms and interacts. Esc opens or backs out of a menu. Skills 1–4 use number keys 1–4. E targets, Q recalls, Tab changes squad doctrine in the field, R commands Heal, Z opens the map, X opens the skill journal, C opens Talents, G shows controls and V pauses.
- The phone uses the fixed left joystick with four skills in an arc, starting with Skill 1 at the lower right and ending with Skill 4 at the upper left. Heal sits farther right, outside the skill arc. Squad doctrine, recall and targeting are on the right. Use the joystick and the Confirm button beside it for menu choices. Use the Back row to dismiss menus. Joystick navigation runs on the title and New Game screens as well as during play. Name fields and system dialogs retain native text and file handling. New Game is available in Settings and uses in-game confirmation before replacing an existing save.
- Desktop left-click in the world requests the existing healer companion action. Mouse or touch selection of game menu options and click-to-move are disabled. Guided travel still uses its existing menu routes. The published baseline's disabled mana mode is retained.
- Slots 5–8 are available through the same instructors, learning requirements and rank upgrades. A successful activation of 1–4 resolves its learned pairing in the same form after the primary release. The pairings are 1→5, 2→6, 3→7 and 4→8.
- The primary pays its existing costs and starts its existing recovery. Its paired effect uses its own rank, native targeting and protection rules, with no extra resource cost or independent cooldown. If the primary requests an approach, the pair waits for release. A failed or interrupted primary never releases its pair. With no legal secondary target the secondary produces no effect or pursuit. Basics never trigger pairs.
- The existing automatic Skill 1 cadence runs only when the hero actually changes position during movement. Manual skills remain available while stationary.

## Separation policy for future chats

- **One-way inheritance:** A new public/main release may be brought **into** the experimental edition only when the change is compatible with the variant's existing gameplay and control philosophy. Port the necessary edition-specific delta onto the **verified published official build**, not onto an unmerged development branch. Do not automatically assume the tip of `main` is publicly released.
- **No reverse inheritance:** Never import variant-only bug fixes or special player preferences into `main` as part of an edition task. The variant's joystick skill arc, left-side Confirm placement, desktop Enter-as-F field interaction, restricted pointer/touch menu actions, disabled click/tap-to-move, skills 1–4 paired to 5–8, and movement-only basic attacks are **edition-exclusive**. Main-game controls, original phone layout, click/tap interactions, combat and v4 saves must remain intact. Any genuine defect found in both editions requires independent investigation against main source, not automatic copying.
- **Conflicts need the owner:** When a new official change contradicts an experimental rule (or its effect is uncertain), stop the conflicting port and ask the owner which behavior takes precedence before altering the variant. Do not silently change either game's design.
- **Publication and refresh:** Updating the edition is **event-driven**, after an actual official publication, not a daily check. The previously enabled daily refresh automation was **disabled at the owner's request on 15 November 2026**. Do not reactivate or create a recurring monitor without a new request. The owner rejected proposed whole-site byte-for-byte integrity gates and other new expensive release tests. Preserve existing source-version checks and Pages deployment serialization. No main merge, official release, Pages/PWA publication, user outreach, or new live variant publication is authorized merely by this handoff. The edition's original no-tests waiver does not waive the main game's normal verification gates.
- **Distribution and saves:** Standard public PC/phone URLs remain `/` and `/phone.html`. Edition URLs are `/tools/webgl-pilot/play/?experience=desktop` and `/tools/webgl-pilot/play/phone.html?experience=phone` at the same official GitHub Pages origin. The edition prefixes browser storage with `gta-cuba:`, uses a distinct cache prefix and nested service-worker scope, and must not overwrite the main game's saves or root worker. Sharing an edition URL shares the experimental layout; sharing the official URL shares the owner's intended public game.

## Updating and removing the edition

Only when an official update has actually been published and the owner requests a variant refresh, read the official Pages build marker and confirm its successful deployment. Port only the existing edition changes onto that exact source. Preserve the edition origin, prefixed storage and cache keys, v4 save format, and fixed controls. Package with `node scripts/build.cjs --package-only --site` and the published release's pinned Pixi asset already present. Stamp the edition SHA using `GITHUB_SHA`. The branch-only `fixed-controls-pages.yml` workflow layers the edition over a package rebuilt from the currently published official SHA. The `github-pages` deployment environment must allow `mod/gta-cuba-edition`. Normal official deployments replace the Pages artifact, so re-run edition publication after refreshing it for each new official release. Keep PR #872 away from main integration and keep the official Pages workflow untouched.

To retire the edition's two URLs, leave the refresh automation disabled, and arrange an explicitly authorized Pages release that excludes the edition subtree. Do not confuse this GitHub Pages path with the old standalone ChatGPT Site. The isolated source branch may be retained for historical reference or separately deleted if authorized. Already installed/offline copies may remain on a device.
